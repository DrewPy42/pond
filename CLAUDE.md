# Pond — working rules for Claude Code

Pond is a self-hosted personal and business finance system by WibbitWorks. A household runs it at home, usually on a Raspberry Pi. The **core** owns the money data: accounts, transactions, splits, categories, Spaces, users, sync, backups and security. Features are added through plugins called **LilyPads**.

## Hard rules

1. **Stay inside v1 scope.** If a task needs something listed under "Later" in `docs/scope-v1.md`, stop and ask. Do not build it "while you're in there."
2. **Money is integer cents.** Use the `amount_cents` integer columns. Never use floats, and never use decimal strings in logic. Signs follow SimpleFIN: positive means money into the account.
3. **Splits must add up.** Every transaction has at least one split, and its splits sum exactly to the transaction amount. Reports read splits, never raw transactions. Any write path that breaks this invariant is a bug.
4. **Every primary key is a UUID**, generated by the app (UUIDv7). Keep SimpleFIN's own IDs in `external_id`.
5. **Permissions go through one place.** Every API route resolves the acting user and Space through the shared auth middleware and checks Space membership and role. Deny by default. Never add a route that skips it.
6. **LilyPads never touch core tables.** They use the core API through `ctx`. They may only query their own `lp_<padId>_*` tables directly.
7. **Secrets are encrypted at rest** with the core crypto module (`server/src/crypto`). This covers SimpleFIN access URLs, AI keys, TOTP secrets, SSNs and EINs. Never log them, never return them in API responses unless it is an explicit, re-authenticated reveal, and never write them to the audit log.
8. **Validate all input with zod** at the route boundary. Queries go through Drizzle; no string-built SQL.
9. **Migrations are forward-only** and must run on a database restored from an older backup.
10. **Ask before adding a dependency.** Prefer what's already in the stack. Anything native must build on linux/arm64.

## Stack

- **Language:** TypeScript (strict) everywhere, Node LTS
- **Backend:** Express, zod, Drizzle ORM on SQLite (better-sqlite3, WAL mode), pino logging
- **Frontend:** Vue 3, Vite, Pinia, Vue Router, **Vuetify 3 only** (no Bootstrap or other CSS frameworks)
- **Brand theme:** WibbitWorks palette as a Vuetify theme (light + dark):
  - Froggy Green `#6CC24A` (primary), Lilypad Teal `#3FBF9D` (secondary), Deep Navy `#1C2B39` (text/dark surfaces), Soft Lemon `#FEE191` (warning), Cloud Gray `#F5F5F5` (background), accent red `#E85A5A`
  - **Contrast rule (WCAG AA, 4.5:1 for text):** green and teal are accent colors, never text on light backgrounds, and never with white text. Primary buttons use navy text on green. Links use dark teal `#1B7560`. Money amounts use darker red and green variants that pass 4.5:1 on the background; always pair color with a sign or icon, never color alone.
  - Logos and icons live in `apps/web/public/brand/` as SVG.
- **Auth:** argon2 (Argon2id), otplib (TOTP), server-side sessions in SQLite
- **Testing:** Vitest. Ledger math, permission checks, sync de-duplication and restore must have tests.
- **Packaging:** Docker, multi-arch (linux/arm64 + linux/amd64), Caddy in front for HTTPS
- **Monorepo:** pnpm workspaces

## Working style

- Small, reviewable changes, one milestone at a time (see `docs/scope-v1.md`).
- When the spec is wrong or silent, say so and propose a change to the relevant doc; don't silently diverge. Record real decisions in `docs/decisions.md`.
- Push back on anything that is unsafe, over-scoped, or won't run well on a Raspberry Pi.
